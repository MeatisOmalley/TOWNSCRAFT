# Four more Very Low experiments, 386SX-25

The selected changes average **9.907 FPS**, versus **7.893 FPS** before this
round: **25.5% more frames per second**, or **20.3% less time per frame**.
This approaches the 10 FPS target without rounding a result below 10 upward.

Configuration: 386SX-25 interpreter, 4 MiB, Trident VGA, compact 1024-block
world, 80x50 view, **0 textured / 4 flat blocks**, Very Low distant terrain.
Each timing result contains three post-fixture repeats, six scenes and 32
measured frames per scene (576 total), with PASS results and stable hashes.
Simulation is frozen: these measure graphics/background-world throughput.
Reference redraws and framebuffer dumps are separate, untimed evidence.

| Experiment, measured individually | Overall FPS | Decision |
| --- | ---: | --- |
| Previous baseline | 7.893 | Reference |
| Limit background column preparation to useful reach | 9.657 | Enable at 80x50 |
| Reuse distant bands across small pose changes | 7.931 | Leave disabled; negligible gain and potential lag |
| Rasterize flat polygons directly at 80x50 | 8.059 | Enable at 80x50 |
| Transpose VGA packing with unaligned words | 7.842 | Leave disabled; slower despite identical output |
| Selected streaming + flat raster | **9.907** | Default shared optimization |

The streaming change keeps the 25-slot cache capacity. Only opportunistic
background preparation narrows its search, using max(view distance + 16, 28)
blocks to retain lighting reach and the 27-block hostile spawn radius plus a
neighbor. Critical requests and pinned body columns bypass the limit. Boot
preparation and full drains retain their original behavior. This reduces work
without tying graphics behavior to CPU detection.

The flat raster uses the 80x50 sample grid directly instead of scanning the
intermediate 160x100 grid and discarding samples. Polygon edge rounding changes
slightly. Texture masks, sharp overlay bands, clipping and the existing planar
target remain supported. Other view resolutions use the original raster.

Edit-call work is additional to the render FPS: its mean falls from 75.231 ms
to 4.046 ms, giving approximately 6.0 complete edit/render cycles per second
after this round. The graphics replay does not establish unrestricted gameplay
or AI performance. Dense scenes still run below 10 FPS.

Both Textured distance and Flat distance menu controls now change by the
requested **2 blocks per step**. Their existing 0/4 minima and CPU limits remain.

## Validation and limits

All 18 focused menu, graphics-policy, overlay, cache, lighting, raster and packing
checks pass, along with four existing packing compatibility checks. The real
4 MiB cache/lighting harness covers cold loading, polling,
canonical light propagation, torch removal and roof reopening. Native raster
checks cover clipping, guard bytes, sharp bands, restored state and unchanged
output outside 80x50. Standard and large-world production builds link. The
normal-route guest reference test passes with 228 frames and zero mismatches;
six images were dumped and the walk, down, up and house views reviewed.

A faster diagonal diagnostic moves half a block along each horizontal axis
per frame and crosses column boundaries. Its reference redraw finds 14
mismatches out of 228 frames in the previous baseline, streaming alone and the
selected pair, at the same camera poses. These are inconclusive: the second
redraw also advances incremental distant-panorama state. The generic benchmark
CLI already excludes diagonal renderer verification. This
does not establish a collection-cache bug. Diagnostic VMs and raw reports are
preserved, and their timing is excluded here.
The isolated near-only rerun of the selected pair passes the same fast route:
**228 frames, zero mismatches**, with distant terrain disabled. Together with
the normal far-enabled reference pass, this isolates the fast-route failure
to the comparison involving incremental distant output.
